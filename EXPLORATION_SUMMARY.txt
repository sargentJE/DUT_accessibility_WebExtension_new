================================================================================
DATA PROCESSING PIPELINE
================================================================================

STEP 1: FORM SERIALIZATION
  Function: serializePageForm() [/js/popup.js:980]
  - Collects all form elements on current page
  - Handles checkboxes as arrays
  - Returns flat object per page

STEP 2: STORAGE
  Location: chrome.storage.sync
  Keys: ${origin}_page{N} for each page
  Auto-save: Triggered on form change (debounced)

STEP 3: SESSION CREATION
  Function: createSessionIfNeeded() [/js/popup.js:1124]
  - POST /api/submit-review
  - Receives submissionId
  - Stored in chrome.storage.sync

STEP 4: DATA GATHERING
  Functions: 
    - gatherAllPages() [/js/popup.js:1341]
    - gatherRequiredSchemas() [/js/popup.js:1352]
  - Collects all page data from storage
  - Retrieves validation requirements

STEP 5: COLLISION DETECTION & FLATTENING
  Function: finalizeSubmission() [/js/popup.js:1364]
  - Two-pass algorithm:
    1st pass: Identify field name collisions across pages
    2nd pass: Apply page prefix (page{N}_) only to colliding fields
  - Non-colliding fields keep original names (backward compatibility)
  - Adds page completion metadata

STEP 6: VALIDATION
  Function: validateReviewCompleteness() [/js/popup.js:2410]
  - Checks required fields per page
  - Validates checkbox groups have selections
  - Reports missing fields to user

STEP 7: SUBMISSION
  Endpoint: PUT /api/reviews/{sessionId}
  - Sends flattened formData + metadata + complete flag
  - Includes JWT Bearer token in Authorization header
  - Handles various HTTP status codes (401, 404, 413, 429, 5xx)

STEP 8: CLEANUP
  On success:
  - Clear all stored form data
  - Clear session ID
  - Clear website URL
  - Save submission receipt
  - Navigate to page 1

================================================================================
KEY COLLISION HANDLING
================================================================================

Problem: Same field name on multiple pages would overwrite

Solution: Two-pass pre-computation
  1st pass: Build set of all field names, identify collisions
  2nd pass: Apply page prefix ONLY to colliding fields

Example:
  Without collision: main_features_ease (only on page 3)
  With collision: contact_info_ease (might appear on multiple pages)
    -> page3_contact_info_ease, page4_contact_info_ease, etc.

Backward Compatibility:
  - Non-colliding fields keep original names
  - Existing API contracts maintained
  - Previous data formats still supported

STORAGE STRUCTURE
================================================================================

CHROME STORAGE - SYNC (across browsers):
  ${currentOrigin}_page{N}: Object of form data for page N
  ${currentOrigin}_req_{N}: Array of required field objects for page N
  ${currentOrigin}_session_id: Session/submission ID string
  ${currentOrigin}_site_url: Website URL being reviewed
  ${currentOrigin}_last_page: Last visited page number
  ${currentOrigin}_receipt: Submission confirmation timestamp

CHROME STORAGE - LOCAL (device-specific):
  token: JWT authentication token
  syncQueue: Array of failed requests for offline retry
  backendUrl: Backend base URL (configurable)

Key Pattern:
  - Origin-scoped: Allows multiple concurrent reviews
  - Persistent: Survives browser restart
  - Encrypted: Protected by Chrome's storage encryption

================================================================================
ERROR HANDLING & RESILIENCE
================================================================================

HTTP STATUS CODES HANDLED:
  200-299: Success - submission complete
  401/403: Auth expired - redirect to login page
  404: Session not found - prompt new review
  413: Payload too large - reduce response length
  429: Rate limited - retry with Retry-After delay (up to 3 attempts)
  500-504: Server error - queue for offline retry

OFFLINE SUPPORT:
  - Failed requests stored in syncQueue
  - Persisted to chrome.storage.local
  - Automatically retried when connection restored
  - Flushes on 'online' event

VALIDATION CHAIN:
  1. Form-level: HTML5 required/validation attributes
  2. Page-level: checkValidity() on form submission
  3. Checkpoint: Validate page before navigation
  4. Final: validateReviewCompleteness() before server submit

USER FEEDBACK:
  - Toast notifications (success/error messages)
  - Detailed error messages for HTTP status codes
  - Loading overlays and progress indicators
  - Auto-save indicators

ARCHITECTURE HIGHLIGHTS
================================================================================

1. SEPARATION OF CONCERNS:
   - UI/Forms: HTML pages + popup.js
   - Storage: Chrome storage API with origin scoping
   - Networking: Background script (avoids CORS issues)
   - Authentication: Dedicated token.js module

2. OFFLINE-FIRST DESIGN:
   - Auto-save to local storage
   - Queue failed requests
   - Retry on connection restore
   - No data loss

3. SECURITY MEASURES:
   - JWT Bearer authentication
   - CORS-safe background fetch
   - Token stored securely
   - Origin-scoped data

4. USER EXPERIENCE:
   - Auto-save prevents data loss
   - Form state persistence across browser restarts
   - Progress tracking per page
   - Comprehensive error messages
   - Keyboard shortcuts support

5. SCALABILITY:
   - O(n) collision detection (not O(n²))
   - Origin-scoped data allows concurrent reviews
   - Idempotent session creation
   - Efficient array handling for checkbox groups

REQUIRED FIELDS (Per page):
  Page 2: All checkbox groups (input_method, content_access, navigation_pref, challenges)

DEPLOYMENT & RUNTIME
================================================================================

RUNTIME ENVIRONMENT:
  - Chrome MV3 (Manifest V3) Extension
  - Background Service Worker (not persistent)
  - Content Scripts: None (comment: "removed to keep lightweight")
  - Pop-up UI: HTML pages dynamically styled

EXECUTION FLOW:
  1. Extension icon clicked or Alt+Shift+A pressed
  2. popup.html loads (main entry point)
  3. JavaScript initialization:
     - Load user settings (theme, font size, backend URL)
     - Restore session if exists
     - Load last visited page
     - Initialize form with saved data
  4. User navigates pages (1-8)
  5. Forms auto-save on change
  6. Submit triggers finalizeSubmission()
  7. Data sent via background.js to backend
  8. Cleanup and navigation to page 1

MEMORY FOOTPRINT:
  - popup.js: 103KB (minified recommended for production)
  - background.js: 4.6KB
  - Total JS: ~115KB uncompressed

CONCLUSION
================================================================================

This web extension implements a comprehensive accessibility testing and feedback
system. The backend data schema is well-designed with:

- Clear separation of concerns
- Robust error handling
- Offline support with queue persistence
- Flexible data structure with collision handling
- Comprehensive field mapping (80-90 fields)
- Strong authentication via JWT tokens
- Origin-scoped data for concurrent reviews

The data is sent to backend in a flattened JSON structure with metadata,
allowing the backend to easily ingest, validate, and process accessibility
feedback from users with various disabilities.
